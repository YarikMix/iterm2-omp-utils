# Native omp status contracts

`status` owns only the selected profile's nested `terminal.programStatus: true`.
omp is the sole OSC 7501 writer for `idle/working/blocked/done/error`. The package
installs no status hook, lifecycle callback, daemon, cc-status adapter or shell
dispatcher. Notifications, restore, MCP and shell remain independent selections.

The native YAML adapter retains local presence/value inverses, comments and
foreign neighbours under file/address CAS and the existing transaction journal.
Equivalent foreign settings may be reused without claiming ownership. Named
profiles remain distinct; storage readback is not an effective project/provider/
launch-overlay configuration probe. No native `config get/list` is executed.
Native YAML/MCP storage reads reject non-regular files through nonblocking open
and descriptor type checks; a FIFO is preserved and cannot hang planning.
The lifecycle's supplied Runner also covers native parser preparation.
New binding intent retains collision checks; a receipt-guarded inverse restores
the actual original chord even when that original already had a collision.

Version strings are diagnostic, never exact-version gates. Native setting
names/values follow omp's public settings/runtime contract. `it2 --help` has
no OSC advertisement contract and may read private configuration, so discovery
does not execute it or infer receiver support from help/version/API presence.
Selected native configuration can be prepared with receiver delivery explicitly
pending; this does not advertise OSC support or install a hook fallback.
Missing required executable/parser capabilities still block only their consumers.

`native_status` stays pending after storage writes or a connectivity probe.
`doctor --live` may read status for an explicit terminal UUID; this does not
prove event delivery or effective omp configuration. Every present
`ITERM_SESSION_ID`/`TERM_SESSION_ID` must be valid and agree. No active-tab
fallback is allowed; TMUX live acceptance is not established.

`runtime/terminal_identity.py` owns generic UUID/environment parsing, kernel
PID-birth/foreground checks, private record validation and own-TTY observation.
The identity extension is a separate main-TUI bridge, not another event writer.
The runtime payload preserves `runtime/omp_config.ts` and root `vendor/yaml`
relative layout. Its retained-file allowlist excludes retired hook/notifier/
restorer trees. Ordinary shell does not depend on Bun or omp identity.

All offline regressions and live idle/working/blocked/done/error acceptance
remain NOT RUN until Task10. Export inventory is not receiver or standalone proof.
